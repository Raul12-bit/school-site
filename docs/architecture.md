# Архитектура следующего этапа

## Границы приложения

```text
Web client (React)  ──HTTPS──>  API (Fastify)  ──> PostgreSQL
                                      └──────────> S3/облачное хранилище изображений
```

Публичный интерфейс не получает административных прав по состоянию кнопок: API проверяет сессию, роль и входные данные для каждого защищённого действия.

## Модули API

- `auth` — регистрация, вход, выход, сессии, bcrypt/argon2-хеши, подготовка восстановления доступа;
- `users` и `roles` — роли `USER`, `TEACHER`, `ADMIN`, изменение ролей только администратором;
- `school-info`, `news`, `teachers`, `schedules`, `events`, `gallery`, `feedback` — независимые CRUD-модули;
- `media` — выдаёт короткоживущие разрешения на загрузку в object storage, хранит только метаданные и URL в БД;
- `admin` — показатели dashboard, аудит критичных изменений.

## Модель данных

Базовые таблицы: `users`, `roles`, `user_roles`, `news`, `teachers`, `classes`, `schedule_entries`, `events`, `gallery_albums`, `gallery_items`, `feedback_messages`, `feedback_replies`, `school_information`, `media_assets`, `audit_logs`.

Все редактируемые тексты используют отдельные поля `*_kk`, `*_ru`, `*_en`; API выбирает запрошенный язык и возвращает казахскую версию, если перевода нет. Пароли, изображения и обращения не будут храниться в JavaScript, JSON-файлах или `localStorage`.

## Этапы разработки

1. Подтвердить визуальный фундамент (текущий этап).
2. Поднять PostgreSQL/Prisma, миграции, API и безопасную авторизацию с ролями.
3. Подключить управляемые через API новости, учителей, расписание, события и медиа.
4. Создать защищённую адаптивную админ-панель и обращения администрации.
5. Провести security-проверку, тесты, настройку production-переменных и развёртывание.
